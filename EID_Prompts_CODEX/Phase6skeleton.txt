Phase 6 — Counter-Attack Intelligence
Objective

Create an operational cockpit that tells MOEX:

What to close.
What to decide.
Who to relaunch.
Who to attack.
Which subject is becoming dangerous.
What evidence supports it.

The system must be usable by non-technical people. The user should not need to understand chain logic, onion scoring, consultant tiers, or workflow complexity.

The current repo already has the key ownership rule: primary pending, secondary pending within 10 days, secondary expired returning to MOEX, all replied returning to MOEX, REF returning to contractor, terminal visa closing the item. The Document Command Center already exposes “Secondaire expiré” as a secondary tag. Phase 6 should surface these rules as action buckets.

Recommended Final Phase 6 Structure
6A — Build Counter-Attack Action Artifact
6B — Add Counter-Attack Read Endpoints
6C — Build Simple Cockpit UI
6D — Add Export, Treated State, Monthly AI Pack

This is better than the current documented structure because the current docs are still centered on an “Intelligence filter/list” page. The repo confirms Phase 6 was planned as an unimplemented Intelligence layer with 6A/6B/6C/6D sub-plans, but those plans are passive compared to the counter-attack concept.

Core Design Rule

Phase 6 must not ask the user to analyze.

It must say:

Do this first.
Here is why.
Here is the evidence.
Here is the action.

Default mode:

Simple / idiot-proof / action buckets

Optional later mode:

Expert / filters / forensic analysis
